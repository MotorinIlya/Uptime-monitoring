# Стратегия ветвления

## Обзор

В репозитории используются две основные ветки: `main` и `rc`.

| Ветка | Назначение | Источник PR | Прямой push |
|-------|-----------|-------------|-------------|
| `main` | Продакшн-код, стабильный релиз | Только из `rc` | Запрещён |
| `rc` | Интеграционная ветка для подготовки релиза | Любые ветки (`feature/*`, `bugfix/*`, `hotfix/*` и т.д.) | Запрещён |

`main` является веткой по умолчанию (default branch).

## Схема потока изменений

```
feature/some-feature
        │
        ▼
       rc          <── любые ветки (feature/*, bugfix/*, hotfix/*)
        │
        ▼
      main         <── только из rc
```

## Правила для ветки main

- **Назначение**: содержит только проверенный, готовый к продакшену код.
- **Прямой push**: запрещён.
- **Pull Request**: только из ветки `rc`.
- **Требования к PR**:
  - Все status checks (CI) должны пройти.
  - Ветка должна быть up-to-date относительно `main`.
- **Force push**: запрещён.
- **Удаление ветки**: запрещено.

## Правила для ветки rc

- **Назначение**: интеграционная ветка для стабилизации перед релизом.
- **Прямой push**: запрещён.
- **Pull Request**: из любых веток, кроме `main`.
- **Требования к PR**:
  - Все необходимые status checks должны пройти.
  - Ветка должна быть up-to-date относительно `rc`.
- **Force push**: запрещён.
- **Удаление ветки**: запрещено.

## Чеклист перед созданием PR

- Все тесты проходят локально.
- Код отформатирован согласно стандартам проекта.
- Ветка обновлена относительно целевой ветки (`git pull --rebase`).
- Нет конфликтов слияния.
- Описание PR имеет смысл, описывает сценарийно что было сделано
- Добавлены или обновлены тесты для новых изменений (если требуется).
- Обновлена документация (если требуется).

## Что запрещено

- Прямой push в `main` и `rc`.
- Force push в `main` и `rc`.
- Создание PR из произвольных веток в `main`.
- Создание PR из `main` в `rc`.
- Merge PR без прохождения обязательных status checks.
- Удаление защищённых веток.
